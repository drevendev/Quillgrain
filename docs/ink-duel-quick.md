# ИнкДуэль: один исходник — одна пара

Реализовано по #27–29 отдельным форматом `duel.quick-*/v1`. Исторические игры,
ключи, файлы ответов и критерии не конвертируются. Команды ниже не вызывают модель.

## Сначала план

Подготовьте приватный JSON `duel.quick-sources/v1` с `sources` и `conditions`.
У каждого источника ровно поля `id`, `work_id`, `group`, `source_text`, `purpose`,
`rights_reviewed: true`, `meaning_reviewed: true`. Текст — данные для переработки;
редактор предварительно проверяет права, смысл, отсутствие утечки из обучающих
примеров и удержание необходимых фактов в задании. Выходов модели здесь ещё нет.

У каждого условия — уникальный `id`, `kind: model | original` и непустые строки
`model`, `profile`, `examples`, `brief`, `reasoning`, `session`. Они фиксируют реальные
версии/режимы либо явное `UNKNOWN`, а не предполагаемую сопоставимость условий.
Для одного источника задача и исходные сведения должны быть одинаковы; намеренное
различие brief — отдельный фактор и ограничение вывода.

```text
qg duel quick-plan --sources PRIVATE_SOURCES.json --seed 42 --budget 30 --out NEW_PLAN
```

Бюджет по умолчанию — 30 дуэлей; можно указать меньше. При недостатке источников
используются доступные. Дополнительные условия не меняют бюджет. Выборка
стратифицируется по категориям и предпочитает разные произведения, число показов
условий и пар выравнивается внутри бюджета. Ориентация по обходу графа гарантирует
разницу левых и правых показов каждого условия не более одного. Неполное покрытие
пар допустимо; точная балансировка каждой категории при малом бюджете невозможна.
Повтор ID и повтор после Unicode NFKC/нормализации пробелов отклоняются. Это не
семантический поиск почти одинаковых отрывков: редактор проверяет их отдельно.

`plan.private.json` фиксирует seed, бюджет, хеши исходников и назначенные пары до
генерации/чтения ответов. Сохраните его неизменным. Хеш проверяет согласованность,
а не доказывает время создания плана или подлинность издателя.

## Затем два результата на источник

На следующем, явно разрешённом запуске получите **только два** назначенных
варианта для каждого источника. Команда подготовки принимает массив объектов:

```json
{
  "source_id": "fictional-source-1",
  "source_text": "Исходный синтетический текст.",
  "variants": {
    "condition-a": {
      "text": "Неотредактированный ответ.",
      "sha256": "SHA256_UTF8_TEXT",
      "raw_sha256": "THE_SAME_SHA256",
      "source_sha256": "SOURCE_SHA256_FROM_PLAN",
      "condition": {"id": "condition-a", "kind": "model", "model": "fixture", "profile": "none", "examples": "none", "brief": "brief-v1", "reasoning": "low", "session": "isolated"},
      "plan_digest": "DIGEST_FROM_PLAN",
      "status": "LIVE"
    },
    "condition-b": {"...": "Второй назначенный вариант с теми же полями"}
  }
}
```

У `original` текст обязан совпасть с исходником, статус — `ORIGINAL`. Для всех
синтетических вариантов статус — `MOCK`; упаковка требует `--synthetic`. MOCK
нельзя выдать за LIVE. Сырые ответы и квитанции реальных запусков сохраняются
отдельно; упаковщик проверяет заявленные хеши и план, но не делает внешнюю
аттестацию модели. Не редактируйте ответы и не перегенерируйте совпадения ради
более удобного голосования.

```text
qg duel quick-prepare --plan NEW_PLAN/plan.private.json --cases PRIVATE_OUTPUTS.json --out NEW_GAME
```

Получаются слепой JSON, отдельный приватный ключ, копия плана и автономный
`Ink_Duel.html`. Откройте HTML локально или запустите `qg duel serve --session
NEW_GAME/blind-session.json`. В HTML нет ключа, профиля и исходных метаданных.
Создание планов/игр/отчётов не перезаписывает существующую папку.

## Оценка и остановка

Под двумя карточками — два необязательных комментария. Одна общая оценка:
«← Сильно лучше», «← Чуть лучше», «Равно», «Чуть лучше →», «Сильно лучше →».
Дефолтного голоса нет. Клик или клавиши 1–5 сохраняют оценку и открывают следующую
пару. Во время ввода комментария клавиши не голосуют; повтор/двойной клик защищён.
Совпадающим текстам доступно только «Равно», в отчёте это неоднозначность.

Черновики сохраняются локально по session ID и digest; экспортируйте файл ответов
для резервной копии. Через меню доступны импорт и «Остановиться и посмотреть
итоги». После остановки голосование закрывается, черновик сохраняется и исключается
из статистики. Только теперь можно открыть отдельный ключ и выгрузить сводку без
текстов/комментариев. Импорт из другой игры, откат и изменение уже принятых голосов
отклоняются. Старые форматы импортируйте в соответствующий старый клиент.

```text
qg duel report --session NEW_GAME/blind-session.json --answers ANSWERS.json --key NEW_GAME/answer-key.private.json --out NEW_REVIEW
```

Для ACTIVE или исторических ответов явное решение владельца передаётся `--stop`.
Входные файлы не изменяются. Отчёт содержит planned/committed, экспозиции
категорий/условий/сторон, число исходников/произведений, прямые пары с `n` и
раздельные порядковые категории силы голоса. Сильный голос не весит вдвое больше.
При `n=0` результат неизвестен, не ничья. Общей рейтинговой таблицы нет.

Поддерживаются исторические numeric-v1, pair-v2 и multi-v3: оси качества,
похожесть и догадки остаются отдельными; общая оценка не выводится из них.
Если старый ключ не имеет ID исходников, их число остаётся неизвестным.
Опциональный `--source-map` принимает замороженный `duel.source-map/v1`:
`session_id`, `bundle_digest`, `cases` в точном порядке игры, у каждой записи
`id`, `source_id`, `work_id` (и при наличии `normalized_sha256`), плюс `digest` по
qg-json-v1. Названия произведений не используются для догадки о совпадениях.

Экспорт по умолчанию — только агрегаты, ID условий и их факторы, контрольные
суммы и ограничения; без текстов, комментариев, ключа и самого профиля. При
публикации всё равно проверьте чувствительность ID и метаданных условий.
Малые/неравные выборки и смешение модели, профиля, примеров, brief, reasoning и
сессии не позволяют приписать эффект одному фактору. Без комментариев причины
предпочтений неизвестны. Структурная проверка не подтверждает качество голоса.
