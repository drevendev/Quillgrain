# План художественного опыта Ink Duel

Формат `duel.quick-*/v2` различает переработку готовой прозы, продолжение
и новую сцену по факт-пакету. Один вход показывается один раз в двух условиях;
бюджет по умолчанию — 30, можно меньше. План фиксируется до генерации.
Команды не вызывают модель и не меняют старые кампании.

Публичный пример [fiction-duel-v2.json](../examples/synthetic/fiction-duel-v2.json)
содержит шесть оригинальных синтетических заданий и фиктивные контрольные
идентичности. Он проверяет контракты и не является проведённым опытом:

```text
qg duel quick-plan --sources examples/synthetic/fiction-duel-v2.json --seed 42 --budget 6 --out out/new-fiction-plan
```

## Манифест и фиксация исследования

`duel.quick-sources/v2` имеет ровно поля `schema_version`, `research`,
`conditions`, `sources`, `reference_work_ids` и `quotas`.

`research` фиксирует `question`, `stage: development | reserve`, численный
`word_budget: {min, max}`, `context_policy`, `comparison_goal: screening |
version_change`, `control_condition`, `controlled_factors` и `limitations`.
Для `version_change` требуется конкретное предыдущее условие с отличающимся
снимком профиля; контроль нельзя заменить отсутствовавшей версией.
Указанные controlled factors должны действительно совпадать и быть известными.
Если условия намеренно различаются, оставьте фактор вне этого списка и учитывайте
его в ограничениях вывода.

Условие сохраняет поля quick-v1: `id`, `kind: model | original`, `model`,
`profile`, `examples`, `brief`, `reasoning`, `session`. Значения фиксируют
реальные настройки/идентичности либо честное `UNKNOWN`. Новое `profile_snapshot`
содержит `context_build_id` и полную цепочку `packs: [{id, version, digest}]`.
Для baseline без профиля используйте `profile: none`, `profile_snapshot: null`;
для original snapshot также `null`. Само наличие этих деклараций не аттестует модель.

`quotas` — `null` для неполного сбалансированного дизайна либо точное число
выбранных входов по группе. Сумма квот не превышает бюджет; недоступная группа
или недостаток материала дают явную ошибку. Без квот недостаток источников
уменьшает фактический план, который виден до начала. Дополнительные условия
не увеличивают число дуэлей.
Seed v2 — целое в диапазоне от `-(2^53-1)` до `2^53-1`, чтобы JSON сохранял
его точно и в Python, и в браузере. Имена ключей канонизируются в порядке
Unicode codepoints, включая числоподобные имена групп.

## Вход сцены и происхождение

Каждый `source` содержит `id`, `work_id`, `group`, `split`, `task_kind`,
`source_text`, `fact_pack`, `purpose`, `rights`, `meaning_reviewed`, `authorship`.

| Поле | Значения и проверка |
| --- | --- |
| `task_kind` | `rewrite`, `continuation`, `new_scene` |
| `source_text` | Непустой исходник для rewrite/continuation; строго `null` для new_scene |
| `fact_pack.characters` | Массив `{id, relations, knowledge}`; для новой сцены нужен хотя бы один персонаж |
| Остальные fact slots | `action`, `conflict`, `facts`, `stop` |
| `information_status` | `fictional`, `concept`, `factual` |
| `document_form` | `scene`, `direct_description`, `conditional_reasoning`; для new_scene — `scene` |
| `rights` | `{reviewed: true, basis, evidence_ref, permitted_uses}`; требуется разрешённый `local_evaluation` |
| `meaning_reviewed` | `true` после проверки исходного смысла/границ задания |
| `authorship` | `human`, `ai_assisted`, `unknown`, `synthetic_ai_prepared`; это статус входа, не доказательство происхождения ответа |

Права проверяются для фактического материала и применения. Receipt хранится
локально; публичная доступность не подменяет основание использования.
Модельные ответы и их возможность распространения проверяются отдельно.

Источник/нормализованное содержимое не повторяются под новым ID. Для новой
сцены сравнивается канонический факт-пакет с NFKC/нормализацией пробелов.
Произведение не может одновременно принадлежать development и reserve;
пересечение с `reference_work_ids` отвергается. Близкие по смыслу задания
дополнительно проверяет редактор: это не семантический поиск дубликатов.

Факт-пакет содержит общий смысл задания, стиль передаётся отдельно. Поля и
директивы не предназначены для дословной вставки в прозу. Статус концепции
не навязывает повторение «мог бы»; реальная условность сохраняется. Объём
определяется ходом сцены, а не универсальной нормой около ста слов.

## Результаты и упаковка

`duel.quick-plan/v2` включает исходный манифест, seed, бюджет, назначенные пары
и `input_sha256`/`normalized_sha256` каждой строки. Проверка плана заново
воспроизводит назначение по сохранённому манифесту. Хеш проверяет согласованность,
а не доказывает время фиксации или подлинность издателя.

После отдельно разрешённого запуска для каждой строки передаётся объект:

```json
{
  "source_id": "scene-0",
  "input_sha256": "INPUT_HASH_FROM_PLAN",
  "variants": {
    "previous": {
      "text": "Exact raw writer response",
      "sha256": "SHA256_UTF8_TEXT",
      "raw_sha256": "THE_SAME_SHA256",
      "input_sha256": "INPUT_HASH_FROM_PLAN",
      "condition": {"...": "Exact condition object from the plan"},
      "plan_digest": "FROZEN_PLAN_DIGEST",
      "status": "LIVE"
    },
    "candidate": {"...": "The other assigned condition with the same fields"}
  }
}
```

Сохраняются все сырые попытки и реальные квитанции генерации вне публичного Git.
LIVE, MOCK и ORIGINAL различаются. `--synthetic` разрешает только MOCK, включая
синтетическую проверку original. Ни совпадения, ни промах длины не запускают
скрытую регенерацию. У модельного ответа механически проверяется заданный word
budget. ORIGINAL сохраняется дословно; его фактическая длина записывается.

```text
qg duel quick-prepare --plan PRIVATE_PLAN/plan.private.json --cases PRIVATE_OUTPUTS.json --out NEW_GAME
```

В слепом v2 bundle находятся только безопасное пояснение состава исследования,
task kind, purpose и две карточки. Ключ, fact packs, rights receipts, snapshots
и mapping остаются в отдельных локальных файлах. ORIGINAL поддерживается
только для rewrite и обязан совпасть с исходником. Для continuation/new_scene
такое условие отвергается; отсутствующий оригинал не достраивается автоматически.

Ответы сохраняют совместимый `duel.quick-answers/v1`: пять порядковых значений,
два комментария и строгая привязка к session ID/digest. Один и тот же формат
ответа не позволяет перенести голос на другой bundle. Quick-v1 и исторические
numeric/pair/multi по-прежнему читаются с прежней семантикой.

## Разбор и комментарии

До голосования видны тип задания и роль оригинала, без соответствия сторон
условиям. В меню можно прочитать сохранённый раунд, не меняя его оценку.
После завершения или явной остановки ключ раскрывает условия и версии.

`duel.partial-report/v2` показывает фактическое покрытие и прямые встречи с n,
task kind, происхождение показанных текстов, группы и силу предпочтения.
У старых файлов отсутствующие сведения остаются `UNKNOWN`. Проценты разных
соперников не складываются в рейтинг; сильный голос не весит вдвое больше.
Относительная победа не означает абсолютного одобрения, пригодности к публикации,
точности канона или улучшения отсутствовавшей в контроле версии.

```text
qg duel report --session NEW_GAME/blind-session.json --answers ANSWERS.json --key NEW_GAME/answer-key.private.json --out NEW_REVIEW
```

Для ACTIVE/исторических ответов нужно явное `--stop`. Draft не входит в счёт.
Опциональный `--comments-out NEW_PRIVATE_DIR` создаёт отдельно
`duel.comment-review/v1`: точные комментарии, card ID, сторону и исходный голос.
Одинаковая заметка на двух карточках имеет общую группу внутри раунда.
Наличие фразы, редакторская интерпретация и причина остаются отдельной работой,
без автоматического продвижения правила. Экспорт агрегатов по умолчанию
не содержит прозы и комментариев; перед внешней передачей проверяются также ID
и metadata условий. Пять кнопок и два необязательных поля сохраняются.
